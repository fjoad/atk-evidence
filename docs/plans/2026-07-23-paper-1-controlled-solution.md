# Paper 1 Controlled Solution — Post-Reconstruction Design

**Goal:** After Paper 1's literal reconstruction, confirmatory assessment, and
LaTeX verdict are complete and frozen, design and evaluate the detector we
would use to solve the underlying electricity-theft problem on scientific
grounds, unconstrained by the paper's methods.

**Status:** Deferred design note. No implementation, tuning, or execution is
authorized before the checkpoint below.

## Why this is separate

This phase asks a different question from reproduction:

> What method can detect the named attacks or real theft reliably on untouched
> customers, and can it exceed the paper's reported performance under a
> statistically valid evaluation?

It cannot repair or replace the reproduction verdict. The literal report is
frozen first so that a successful new method cannot be presented as evidence
that the published method reproduced, and a failed new method cannot be used
to excuse the published results.

“Beat the paper” means exceeding the reported result pattern on comparable
data while using an honest untouched test set, repeated runs, uncertainty, and
predeclared selection rules. If the paper's metrics are internally
incomparable, the primary targets become ROC-AUC, PR-AUC, and DR at fixed
validation-selected FA rates; any paper-number comparison is labeled with its
limitations.

## Current diagnosis carried into this phase

The exploratory literal branch currently shows that LSTM-SAE seed 11 has AUC
51.89%, and even a test-label oracle threshold reaches only 55.52% balanced
accuracy, so threshold retuning cannot recover the reported 86% DR / 12% FA
operating point from this learned score. Its reconstruction score is
effectively mean squared standardized input under zero reconstruction and is
nearly identical to FC-SAE's score.

The leading mechanism is an input/output-domain mismatch: joint z-scoring makes
most inputs negative, while the paper-selected sigmoid/Softmax decoders cannot
produce negative reconstructions. This is **INFERRED**, not yet causally
isolated. The source evidence remains
`studies/atk-2022-deep-autoencoder/results/table_2_neural_score_sanity.json`
and the durable interpretation remains in `docs/EVIDENCE-AND-LEARNINGS.md`.

## Proposed research tasks

Treat two problems separately:

1. **Known-attack detection:** training may use examples generated by the six
   registered attack transformations. This measures in-distribution
   recognition of the paper's synthetic attacks.
2. **Novel anomaly detection:** training uses benign data only, and evaluation
   includes held-out attack families or other anomalous behavior. This measures
   whether the method generalizes beyond transformations it has already seen.

Results from the easier known-attack task may not be advertised as general
electricity-theft detection.

## Data and evaluation design

1. Split customers/meters into train, validation, and test before scaling,
   attack generation, windowing, or oversampling.
2. Fit imputation and normalization on training data only. Preserve an
   untouched, naturally distributed test set; never apply ADASYN to validation
   or test data.
3. Generate synthetic attacks separately inside each customer partition so
   that a malicious test profile cannot share its underlying benign day with a
   training example.
4. Use the native temporal units:
   - CER/ISET: 48 half-hour readings per daily profile, optionally with several
     preceding benign days as customer context.
   - SGCC: the chronological daily customer series, with masks for missing
     values rather than an unexplained conversion to 48 inputs.
5. Select thresholds and hyperparameters using validation data only. Report the
   locked model once on test data.
6. Repeat neural training over fixed seeds and bootstrap customers/meters, not
   correlated rows, for confidence intervals.
7. Report ROC-AUC, PR-AUC, DR at validation-selected FA rates of 1%, 5%, and
   10%, calibration, per-attack performance, inference time, parameter count,
   and failure cases.

## Candidate solution ladder

Start with methods matched to the attacks rather than assuming a deep model is
necessary:

1. **Transparent statistical/rule baselines:** daily energy ratio, maximum
   zero-run, flatness/variance, ramp statistics, load-shape reversal
   correlation, and deviation from each customer's historical profile. The six
   synthetic attacks create strong signatures that these checks may expose.
2. **Supervised tabular baseline:** gradient-boosted trees over those features
   for the known-attack task, with class weighting only in training.
3. **Compact temporal classifier:** a 1-D temporal convolutional network or
   GRU operating on the raw profile plus masks/context. Compare it fairly
   against the tree baseline.
4. **Benign-only detector:** masked-profile prediction or forecasting trained
   only on benign customer history, with anomaly score based on calibrated
   predictive residual or likelihood rather than reconstruction MSE alone.
5. **Ensemble only if justified:** combine statistically distinct rule,
   tabular, and temporal scores using validation data, then lock it before test.

The first full candidate should be the smallest method that clears all
predeclared validation gates. A larger architecture is added only when a
specific residual failure justifies it.

## Mechanism-repair experiments

Before proposing a novel architecture, isolate the failure now observed in the
paper-literal autoencoders:

1. z-score inputs with the paper's nonnegative decoder output;
2. z-score inputs with a linear decoder output;
3. `[0, 1]` training-only scaling with sigmoid output;
4. training-only robust scaling with a compatible linear output;
5. the same branches without test-set ADASYN.

This controlled ladder tests whether the current near-zero reconstruction and
input-energy score are caused by the input/output-domain mismatch, leakage
choices, or both. These are improvements/new methods, never paper-literal
reproduction branches.

## Success criteria to freeze later

- Primary statistical targets and the exact relationship to each reported
  paper row.
- Customer partitions, attack-family generalization split, seeds, bootstrap
  procedure, and compute budget.
- Model/search candidates and validation-only promotion rule.
- Minimum improvement over transparent baselines and the reported paper values.
- Stopping rule that preserves every failed and successful candidate.

A credible success must be stable across seeds and customer-level confidence
intervals, not one favorable run. If no honest method beats the reported
numbers, that is reported rather than relaxing the test protocol.

## Required artifacts

- A separate controlled-method contract and implementation namespace.
- Immutable scores, predictions, timings, seeds, and customer partitions.
- A causal ablation table for the mechanism-repair ladder.
- A standalone “recommended method” section or addendum clearly separated from
  the reproduction/rebuttal report.
